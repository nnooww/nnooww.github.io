# 수업 질문 대기열

실습 수업 중 학생이 질문을 신청하고 자신의 대기 순서를 확인하는 웹앱입니다. 첫 화면에서 회원가입 또는 로그인을 선택합니다. 학생과 선생님의 화면은 데이터베이스에 저장된 계정 권한에 따라 구분됩니다. 선생님 화면에서 대기 중인 질문을 열어 답변할 수 있습니다.

## 실행

Windows에서 `start.cmd`를 실행하거나 터미널에서 `node server.js`를 실행합니다. Node.js 22 이상이 필요합니다. 브라우저에서 `http://localhost:3000`을 엽니다. 별도의 패키지 설치는 필요 없습니다.

회원가입 화면에서 학생 또는 선생님을 선택할 수 있습니다. 선생님 계정은 한 개만 만들 수 있으며 이미 존재하면 선생님 선택 항목이 비활성화됩니다. 처음 설치할 때는 `node setup-teacher.js`로 선생님 계정을 미리 만들 수도 있습니다. 이 명령은 기존 선생님 계정이 있으면 두 번째 계정을 만들지 않습니다. 비밀번호는 다른 사람에게 공유하지 마세요.

학생은 이름과 비밀번호(8자 이상)로 가입합니다. 이후 이름과 비밀번호로 다시 로그인할 수 있습니다. 이전 버전에서 이름만으로 가입한 학생은 로그인 상태가 남아 있는 브라우저에서 먼저 비밀번호를 설정해야 다시 로그인할 수 있습니다.

학생 여러 명이 같은 대기열을 보려면 한 컴퓨터에서 서버를 켜고, 같은 Wi-Fi의 다른 기기에서 `http://서버PC의로컬IP:3000`에 접속합니다. 학교 Wi-Fi가 기기 간 접속을 차단하거나 Windows 방화벽이 막으면 접근되지 않을 수 있습니다. 같은 컴퓨터에서 서로 다른 브라우저 또는 시크릿 창으로도 테스트할 수 있습니다.

## 이번 단계의 기능

- 학생 이름과 비밀번호로 회원가입·재로그인, 브라우저 세션
- 회원가입 시 학생·선생님 권한 선택, 선생님 계정은 최대 한 개
- 로그인 뒤 데이터베이스 권한에 따라 학생/선생님 화면 표시
- 질문 제목과 상세 내용 필수 입력
- 질문 등록, 내 질문과 내 대기 순서 확인, 대기 중 질문 취소
- 다른 학생의 질문 제목·내용·이름은 학생 화면과 대기 순서 API에 제공하지 않음
- 선생님 계정 한 개와 로그인, 학생 계정과 다른 역할로 분리
- 선생님 화면에서 대기 중인 학생 질문을 눌러 상세 내용 확인과 답변
- 선생님 전용 DB 조회 화면에서 계정과 질문 기록 확인(비밀번호와 세션 정보 제외)
- 답변 전에는 대기, 답변을 보내면 자동으로 완료가 되고 학생의 내 질문에 답변이 표시됨
- SQLite 데이터베이스 `data/questions.sqlite`에 계정, 로그인 세션, 질문 저장

비밀번호는 무작위 salt와 scrypt로 해시해 저장하고, 로그인 세션은 HttpOnly 쿠키로 관리합니다. 학생의 질문과 답변은 본인과 선생님 계정에만 제공됩니다. 다른 학생에게는 대기 인원과 본인 순서만 제공됩니다. 이 앱은 수업 시연용이며 실제 학생 정보나 민감한 질문을 처리할 운영용 서비스로 설계되지 않았습니다.

## 온라인 시연 배포

GitHub는 코드를 보관하고, Railway의 웹 서비스가 Node 서버를 실행합니다. GitHub Pages만으로는 이 앱의 서버와 SQLite 데이터베이스를 실행할 수 없습니다.

1. GitHub의 `classroom-question-queue` 저장소를 Railway의 새 웹 서비스에 연결합니다.
2. 서비스에 영구 볼륨을 추가하고 마운트 경로를 `/data`로 설정합니다.
3. 서비스 환경변수 `DB_FILE=/data/questions.sqlite`를 설정합니다. `TEACHER_PASSWORD`에는 공백만으로 구성되지 않은 8~128자 비밀번호를 설정합니다. 비밀번호를 GitHub 코드에 적지 않습니다.
4. 시작 명령은 `npm start`입니다. Railway에서 공개 도메인을 생성한 뒤 `/api/health`가 `{"ok":true}`인지 확인합니다.

온라인 서버는 시작할 때 `선생님` 계정(아이디 `teacher`)과 `시연 학생` 계정을 각각 한 개씩 준비합니다. 두 계정의 비밀번호는 `TEACHER_PASSWORD` 값입니다. 이름으로도 로그인할 수 있습니다. 재시작해도 계정을 중복 생성하지 않으며, 환경변수의 비밀번호를 바꾸고 재배포하면 두 계정의 기존 로그인 세션이 만료됩니다. 같은 이름이나 아이디를 사용하는 다른 계정이 이미 있으면 해당 계정을 덮어쓰지 않고 시작을 중단합니다. 온라인에서는 선생님 회원가입이 비활성화됩니다. 다른 학생은 공개 주소에서 회원가입할 수 있습니다.

온라인 시연에는 가상 이름과 질문만 사용하세요. 공개 주소의 학생 가입은 누구에게나 열려 있습니다. 시연용 공통 비밀번호를 다른 사람에게 알려주면 누구나 선생님으로 로그인해 질문과 DB 화면을 볼 수 있으므로 실제 학생 정보나 민감한 질문을 입력하지 말고 시연 후 비밀번호를 변경하세요. Railway 무료 사용량을 다 쓰면 서비스가 멈출 수 있으므로 시연 전에 주소가 열리는지 확인하세요. 로컬 `data/` 폴더와 비밀번호는 GitHub에 올리지 않습니다.

## 확인

`npm test`로 가입 권한, 로그인, DB 조회 권한, 질문 등록, 순서, 본인 질문 취소와 온라인 배포 설정을 검사합니다.
